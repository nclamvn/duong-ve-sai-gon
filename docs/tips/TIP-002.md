## SPECIFICATIONS
- `clock.ts`: `FixedClock(stepHz=60, maxSubSteps=5)`. `advance(dtSeconds) → { steps: number, alpha: number }`; clamp dt ≤ 0.25 s (tab ẩn); accumulator; `alpha ∈ [0,1)`; `tick` counter tăng đơn điệu; `simTime`.
- `events.ts`: `EventBus<TMap>`; `emit(type, payload, {id?})` với `id` → idempotent: cùng `id` emit lần 2 bị bỏ qua và đếm `duplicates`; `on/off`; `drain()` trả log để test/telemetry; ring buffer 512 sự kiện gần nhất.
- `scheduler.ts`: `Scheduler` đăng ký task theo tier `'sim60' | 'ai10' | 'render'`; `runSim(tick)` chạy sim60 mọi tick, ai10 khi `tick % 6 === 0`; `runRender(alpha, dt)`; đo thời gian mỗi tier bằng `performance.now()` → `lastCostMs` (CPU game time cho telemetry).
- `prng.ts`: `mulberry32(seed)` → `{ next(): number, range(a,b), int(a,b), fork(label): Prng }` — `fork` derive seed từ hash(label) để mỗi hệ có stream riêng, deterministic.
- `pool.ts`: `Pool<T>(factory, reset, capacity)`; `acquire()` trả null khi cạn (không grow ngầm) + `stats {inUse, capacity, exhausted}`; `release`.
- `ids.ts`: `EntityId` brand type + `makeIdFactory(prefix)` tăng dần, reset được.

## ACCEPTANCE CRITERIA
- Given FixedClock 60 Hz, When advance 1.0 s chia thành 37 dt ngẫu nhiên, Then tổng `steps` = 60 và `simTime` ≈ 1.0 ± 1/60.
- Given dt = 5 s (tab ẩn), When advance, Then steps ≤ maxSubSteps và không loop vô hạn.
- Given emit `{id:'RADIO_D01'}` hai lần, Then handler chạy 1 lần, `duplicates === 1`.
- Given Scheduler với 1 task ai10, When runSim 60 tick, Then task chạy đúng 10 lần.
- Given `mulberry32(42)`, Then 5 số đầu giống nhau ở 2 lần tạo; `fork('recoil')` khác `fork('ai')`.
- Given Pool capacity 4, When acquire 5 lần, Then lần 5 trả null và `exhausted === 1`; sau release, acquire lại được.
